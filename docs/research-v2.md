## 二、 赛题背景、核心任务与数据集规格

### 1. 任务类型与核心任务 [2, 5, 6]
* **任务类型**：基于大模型的多模态视觉理解与推理（视觉定位 / Visual Grounding）。
* **核心任务**：输入时间同步、空间对齐的可见光（RGB）、热红外（Infrared）与深度图（Depth），定位英文 Query 所指示的目标归一化边界框 `[x1, y1, x2, y2]`。
* **技术挑战**：相比传统仅检测特定类别的任务，视觉定位要求更高层次的认知能力。为了克服单一视觉信息在弱光、遮挡或相似外观物体存在时的局限性，本赛题引入了多源异构视觉模态与文本语义引导，以实现从自然语言到高精度空间位置的映射。

### 2. 统计学关键发现（数据命门）
* **超小目标占绝对主导**：**58.4% 的目标边界框面积小于图像的 1.5%**（中位数目标仅 $25 \times 30$ 像素）。因此，模型在特征提取时必须尽量保持 1080p 全分辨率无损输入，**禁止暴力下采样压缩**，以防小目标特征丢失。
* **深度测量有效区间**：99.7% 的深度像素集中在 0.3m 到 20.0m 范围内。建议采用固定尺度的 8-bit JET 色彩编码映射，这有利于保持全局一致的物理距离语义。
* **测试集防泄漏查重**：在数据预处理阶段，需通过 SHA-256 字节级全哈希比对，严格剔除训练集（Train/Val）中与测试集（Test）同源或高度相似的图像帧，防止模型过拟合与潜在的评估偏置。

### 3. 应用场景与模态协同价值 [3, 4]
本技术在**自动驾驶、智能安防、应急救援、工业巡检**等实际场景中有极高价值：
* **文本模态 (Query)**：作为核心语义引导，限定定位目标的属性与范围。
* **可见光 RGB**：捕捉目标衣着纹理、颜色、外观细节等高频视觉特征。
* **热红外 (Infrared)**：弥补夜间或昏暗光线下可见光的不足，突显热源轮廓，有效区分活体与静物。
* **深度传感器 (Depth)**：提供目标的三维几何信息与空间绝对距离（单位：毫米），结合文本模态排除前后景中无关物体的干扰，提升定位精确度。

## 三、 多模态数据特征与格式规范

### 1. 四模态数据特征 [7]
1. **可见光 (Visible RGB)**：三通道 uint8 格式，取值范围 `[0, 255]`，1080p 原图无损尺寸。
2. **热红外 (Infrared)**：三通道 uint8 格式（通常为单通道热辐射灰度图的三通道副本堆叠），取值范围 `[0, 255]`。发热或高温物体在画面中呈现高亮度。
3. **深度图 (Depth)**：单通道 uint16 格式，像素取值范围 `[0, 65535]`。数值代表相机到物体的物理距离，**单位为毫米 (mm)**。相机的有效测距在 300mm ~ 20,000mm 之间。**像素值为 0** 代表由于反射、缺失或超出量程导致的无效深度值。
4. **文本指令 (Query)**：英文单句描述，指向图像中的唯一目标。

### 2. 学术背景关联 [6, 16, 30]
* **数据集来源**：该数据集由赛题联系人**朱雪峰老师团队（江南大学）**采集 [30]。
* **参考论文**：其团队在 NeurIPS 2025 发表了相关领域的代表性成果 [16]：
  > *Zhu X F, Xu T, Pan Y, et al. Collaborating Vision, Depth, and Thermal Signals for Multi-Modal Tracking: Dataset and Algorithm [C]// NeurIPS 2025.*

### 3. 数据集结构（JSON 示例） [7, 12, 13]
各模态关联信息以 JSON 格式结构化存储，以唯一的 `Query ID` 作为索引。形式如下：
```json
{
  "000000_001": {
    "visible": "Images/visible/XXXXX.png",
    "infrared": "Images/infrared/XXXXX.png",
    "depth": "Images/depth/XXXXX.png",
    "query": "The farthest four-wing drone from the camera.",
    "bbox": [x1, y1, x2, y2]
  }
}
```

## 五、 成绩评价与评估指标

### 1. 核心评估指标 [9]
赛事采用 **准确率 (ACC@0.5)** 作为唯一的性能打分标准。
* **定位正确判定**：预测框 A 与真实框 B 的交并比 (Intersection over Union, IoU) $\ge 0.5$ 判定为定位正确：
    $$\text{IoU}(A, B) = \frac{|A \cap B|}{|A \cup B|}$$
* **准确率公式**：
    $$\text{ACC@0.5} = \frac{\text{IoU} \ge 0.5 \text{ 的有效查询样本数量}}{\text{测试集全部查询样本总数量}}$$

### 2. 异常框无效判定与底线规则 [12, 13]
评测程序会对以下异常边界框进行自动拦截，**一旦出现直接判定为无效预测（IoU 为 0）**：
* **反向坐标**：$x1 \ge x2$ 或 $y1 \ge y2$。
* **坐标越界**：超出范围 `[0, 1]`。
* **数值异常**：包含 `NaN` 或非法字符。
* **无效空框**。
* **基线成绩红线**：参赛团队提交的最终测试集预测成绩**不得低于赛事官方公布的基线成绩**，否则赛事方有权将其认定为无效成绩 [13]。

## 六、 赛事核心红线与约束条件

为了确保比赛的公平性与技术硬核度，官方制定了极严格的红线条款，违反者将**直接取消参赛资格**：

### 1. 算法约束（商业闭源限制） [14]
* **禁止调用商业闭源大模型的在线推理 API**（如 GPT-4o、Claude 等商业闭源模型的远程调用接口）。
* **仅允许使用开源大模型或自研大模型**（如 LLaMA-Grounding、Qwen-VL、InternVL、SAM 等 [8]）进行自主开发、微调与部署。
* **💡 合规预处理方案（商业开源 API）**：
  在构建四模态微调训练集时，文本 Query 的生成与标注工作极为繁重。选手**允许使用商业云平台（如阿里云百炼、智谱 AI 等）提供的开源大模型 API（如 Qwen-VL 开源版本）**进行批量打标和数据预处理。这完全符合“仅允许使用开源大模型”的规定。但**严禁**使用 Kimi、GPT-4o、SenseNova 商业闭源版等未公开权重的模型。

### 2. 公平性与手工打标限制 [14, 18, 21]
* **严禁人工干预测试集**：所有测试集预测必须由算法模型前向传播自主生成。**严禁手工标注测试集目标位置**。
* **严禁弄虚作假**：在数据预处理或开发过程中，如将闭源大模型生成的数据或手工打标的数据伪报、隐瞒为“开源模型生成”或“纯手工打标”，一旦在半决赛代码及技术报告审查环节被发现，将以“弄虚作假”直接取消参赛团队比赛资格及奖项 [21]。

### 3. 数据保密与合规使用 [15]
* 本赛题对**训练数据使用不做约束**，允许自由引入外部公开数据集，但**必须在技术报告中明确注明数据来源、使用方式及预处理流程**。
* **严禁将测试集数据用于模型训练环节**。
* 赛事提供的所有测试集均为专用，**禁止以任何形式在公开平台分享、开源、传播**，或用于非本次赛事相关的商业 and 科研用途。

## 七、 阶段性提交与结果包规范

### 1. 初赛、复赛阶段（结果提交） [13, 17]
* 参赛队伍仅需提交测试集预测结果。
* **提交格式规范**：提交包必须命名为 **`submission.zip`**，解压后仅包含唯一的 **`result.json`** 格式文件。
* **键值约束**：除 `bbox` 字段外，不得修改或删除原 JSON 模板中的任何键值。
* 预测的边界框坐标必须按照 `[x1, y1, x2, y2]` 的归一化浮点数格式输出，并卡在 `[0, 1]` 范围内。

### 2. 半决赛阶段（全要素审查） [17, 18]
晋级半决赛后，提交要求大幅提升，参赛队伍须提交以下四大要素接受专家审核：
1. **算法代码**：完整的、无缺失的算法代码（含数据预处理、模型微调、推理预测全链路），代码需具备清晰注释 [17, 18]。
2. **预测结果文件** [18]。
3. **模型文件与环境说明**：提供训练好的模型权重文件（大文件可提供可靠的网盘链接），并给出环境依赖文件（如 `requirements.txt`），确保可在指定评测机中复现 [18]。
4. **技术报告**：提交详细的 PDF 格式技术报告，报告需严格按照官方大纲撰写。
